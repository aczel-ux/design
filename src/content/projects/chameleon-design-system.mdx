Chameleon is GoTo’s design system: a collection of foundations, components and complete patterns maintained in shared design libraries and code repositories. Although it is not customer-facing in the traditional sense, the team treats it as a product.

I worked on Chameleon from its earliest stage, when it consisted of colors, typography and a small icon set. It grew into a system used across business units and maintained by a dedicated team of designers, developers and a product owner.

## Responsibilities

My main areas included native mobile components for iOS and Android, illustrations, iconography and documentation resources. I created a blueprint and contribution guide used to define component behavior, tokens, dependencies, accessibility and editorial requirements.

## Tokens and themes

GoTo products have their own brand colors, so components reference semantic tokens instead of hard-coded values. Designers can swap product or light/dark theme libraries while preserving the same component structure and implementation contract.

## Iconography

More than a thousand icons were organized with outlined and filled variants, generic names and alternative search keywords. This made the library useful beyond the product where an icon was originally introduced.

## Design and development working together

Foundation resources could be synchronized to the code repository automatically. More complex components followed a documented handoff and implementation workflow, making every released component available to teams across the company.
